# 「新入生の方へ」ページ — Instagram 連携 計画メモ（個人アカウント前提）

このドキュメントは、サイトに **「新入生の方へ」** 用のページを追加し、[募集用 Instagram（@blasters_recruit）](https://www.instagram.com/blasters_recruit/) を情報の中心にしつつ、**新しい情報が上に来る** 見せ方を目指すための計画です。

**確定方針:** Instagram は **個人アカウントのまま**とする。そのため **Instagram Graph API による自動取得・日次バッチ更新は行わない。**

---

## 1. 目的

- **大学サークルの新歓アカウント**向けに、新入生向け情報を集約したページを用意する。
- 情報のハブとして Instagram を置き、サイトから **[募集アカウント（@blasters_recruit）](https://www.instagram.com/blasters_recruit/)** へ必ず辿り着けるようにする。
- **一覧は「新しい順」** に並べる。データの並びは **編集時に新しい項目を先頭に置く**（または JSON をその順でメンテする）運用で満たす。
- **見た目は Instagram に近いテイスト**（縦スクロールのフィード、カード型など）は、サイトの HTML/CSS で寄せる。

---

## 2. 個人アカウントのままにした場合の整理

### 2.1 できること（この方針で採用しやすい）

- サイトに **プロフィールへの目立つリンク**・**固定文言**（「最新はインスタで」など）を置く。
- **公式の投稿埋め込み**（投稿ごとに Instagram が提供する埋め込みコード）を、重要な告知だけページに貼る。
- **リポジトリ内のデータファイル**（例: `data/shinnyusei-feed.json`）に、キャプション要約・日付・インスタのリンクなどを **手動で追記**し、ページはその JSON を読んで一覧表示する。**新しい投稿のたびに JSON の先頭にエントリを足す**だけで、「上に最新」が実現できる。

### 2.2 やらないこと・推奨しないこと

- **公式 API で投稿一覧を自動取得:** 個人アカウントのままだと [Instagram Graph API](https://developers.facebook.com/docs/instagram-api/) の前提（クリエイター／ビジネス＋ Facebook ページ連携など）と揃わず、**今回の主ルートにはしない。**
- **画面上のスクレイピング・非公式ツールでの自動取得:** 規約違反リスクと、仕様変更で壊れやすいため **サイト運用の前提にしない。**

### 2.3 トレードオフ（把握しておく）

- **インスタに投稿した直後**にサイトへ反映されるのは **人の作業が走ったタイミング**（JSON や HTML の更新・コミット）になる。
- 更新頻度が増えても回るように、**JSON の項目テンプレ**や **チェックリスト**（投稿後にサイトも1行足す、等）を決めておくとよい。

---

## 3. 静的サイト（GitHub Pages）で押さえておくこと

- **ブラウザから Instagram の中身だけを自動ではじき取得**する方式は、セキュリティと規約の関係で現実的ではない（上記のとおり）。
- **個人アカウント前提**では、実質の選択肢は次の寄せ方になる。
  - **手動メンテの JSON（または HTML）** ＋ 同一リポジトリで GitHub Pages が配信
  - **公式の埋め込み**（必要な投稿のみ）
  - **Instagram へ遷移させて最新を見てもらう**（導線の設計）

---

## 4. ホスティング

**採用:** これまでどおり **[GitHub Pages](https://pages.github.com/) のまま** でよい。

- 個人アカウント前提では **API 用の GitHub Actions（日次）** は必須ではない。
- 将来、別のデータ源だけ自動化したくなった場合にだけ **Actions** を検討すればよい（Instagram 取得とは切り離す）。

---

## 5. 採用アーキテクチャ（個人アカウント・手動更新）

1. **サイト側**  
   - 「新入生の方へ」用の HTML ページを追加。  
   - お知らせ一覧は **リポジトリ内の JSON**（例: `data/shinnyusei-feed.json`）を `fetch` して描画する形が扱いやすい。  
   - ページ上部に **Instagram プロフィール**へのボタン／リンクを固定で配置。

2. **データ更新（運用）**  
   - Instagram に新規投稿があったら、担当者が **JSON に1件追加**（**常にファイルの先頭が最新**になるようにする、または `date` フィールドで並び替えロジックを固定）。  
   - 変更を **git commit → push** すると、GitHub Pages に反映される。

3. **任意**  
   - 特に大事な1件だけ **Instagram の埋め込み**をページに直書きする。  
   - 画像を自サイトに再アップロードする場合は **権利・肖像の確認** を別途行う（埋め込みやリンクの方が安全なことが多い）。

**イメージ:**  
「インスタが正本。サイトは要約・索引。**並びと文言は人がメンテ**。」

---

## 6. 実装・運用のステップバイステップ（予定）

### 6.1 ページと導線

- 新入生ページの骨格、固定文言、`index.html` 等からのナビ追加。  
- [Instagram プロフィール](https://www.instagram.com/blasters_recruit/) へのリンクを目立つ位置に。

### 6.2 データ形式

- JSON の **キー例**: `date`（並び替え用）、`title` または `caption` の短い要約、`url`（該当投稿またはプロフィール）、`type`（お知らせ／イベント等）。  
- **新しい順**にするルールを1つに決める（「先頭が最新」か「`date` 降順でソート」か）。

### 6.3 フロント

- JSON を `fetch` し、インスタ風カード一覧を表示。  
- フェッチ失敗時は「Instagram で最新をご確認ください」などのフォールバック文言。

### 6.4 運用ルール（サークル内で共有）

- 投稿後のチェック: **○分以内に JSON を更新する**、**週1でまとめて更新** など、現実的な頻度を決める。  
- 権限: リポジトリに書き込める人を限定し、**誰が更新するか** を決める。

### 6.5 フェーズ分けのおすすめ

1. **第 1 フェーズ:** ページ骨格 + Instagram への強い導線 + 手書きのお知らせ数件。  
2. **第 2 フェーズ:** JSON 駆動の一覧＋インスタ風スタイル。  
3. **第 3 フェーズ（任意）:** 重要投稿のみ埋め込みや画像方針の整理。**API 自動化はスコープ外。**

## 8. セキュリティ・コンプライアンス

- 個人アカウントでも、**無断スクショ転載**より **リンク・公式埋め込み**を優先すると安全が高い。  
- サークルサイトであることが分かる表記（大学公式と誤認されないようにする）。  
- 公開リポジトリに **個人情報・トークンを置かない。**
