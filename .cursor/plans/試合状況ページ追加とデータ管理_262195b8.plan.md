## ゴール

- **試合状況ページを追加**し、「いつ」「どこで（会場＋リンク）」「何時から」「結果」が分かる一覧表を作る。
- **試合データを1カ所に集約**し、HTMLを直接いじらずに試合情報を更新できるようにする（簡易な“データベース”）。
- 将来試合が増えても、**データを追加するだけで自動で表が更新**される構成にする。

## 前提と方針

- 現状は静的サイト（`index.html`＋CSS）なので、まずは**フロントエンドのみで完結する構成**を採用します。
- サーバー側の本格的なDBは使わず、**JSONファイルをデータベース代わり**にし、JavaScriptで読み込んで表を生成する方式にします。
- 新しいページは既にナビにある `pages/match.html` を本命とし、このページで試合一覧を表示します。

## 実装ステップ

### 1. 試合データ用JSONファイルの設計

- **ファイル**: `data/matches.json`（新規作成）
- **構造イメージ（1試合ごとに1レコード）**:

```json
[
  {
    "date": "2025-04-20",          // 日付（ISO形式）
    "kickoffTime": "13:00",       // キックオフ時間
    "opponent": "○○大学",         // 対戦相手
    "venueName": "アミノバイタルフィールド",  // 会場名
    "venueUrl": "https://...",    // 会場へのリンク（なければ空文字）
    "homeAway": "HOME",           // HOME / AWAY など任意区分
    "result": {
      "status": "finished",       // scheduled / finished / cancelled など
      "scoreUs": 21,
      "scoreThem": 14,
      "note": "2部●●ブロック第1節" // 備考
    }
  }
]
```

- **ポイント**:
  - `status` により「試合前（結果なし）」か「試合後（スコア表示）」かを判別。
  - `venueUrl` があれば会場名をリンクに、なければテキストのみ表示。
  - 必要に応じて `league`, `season`, `section` なども後から追加しやすい形にしておく。

### 2. 試合状況ページ `pages/match.html` の骨組み作成

- **ヘッダー・フッター**: `index.html` と同じレイアウト・ナビゲーションを再利用。
- **メインコンテンツ構成**:
  - ページタイトル（例：`試合状況`）。
  - シーズンを切り替えるためのセレクトボックス（任意・最初は固定シーズンでも可）。
  - **試合一覧テーブル**:
    - 列例: 「日付」「キックオフ」「対戦相手」「会場」「結果／スコア」「備考」。
    - tbody 部分は JavaScript で `matches.json` から動的に生成。
  - 将来的に「直近の試合」「次の試合」をハイライトするセクションも追加可能な構造にしておく。

### 3. JavaScript でJSONから表を自動生成

- **ファイル**: `js/match.js`（新規作成）
- **主な処理フロー**:
  1. `window.onload` もしくは `DOMContentLoaded` で処理開始。
  2. `fetch('…/data/matches.json')` で試合データを取得。
  3. 日付順にソートし、必要に応じて「過去」「今後」で区切るロジックを追加可能な形で実装。
  4. 各レコードをテーブルの `tr` 要素として生成し、
    - 会場は `venueUrl` があれば `<a href="...">会場名</a>`、なければテキスト。
    - `result.status` が `finished` なら `scoreUs-scoreThem` を表示、`scheduled` なら `-` または「試合前」、`cancelled` なら「中止」などを表示。
  5. 生成した `tr` を `tbody`（例：`id="match-table-body"`）に append。
- エラー時（JSON取得に失敗など）は、テーブル下に「現在、試合情報を取得できません。」といったメッセージを表示。

### 4. スタイル調整（CSS）

- **ファイル**: 既存の `css/stylesheet.css` に追記。
- **内容**:
  - 試合一覧テーブル用のクラス（例：`.match-table`, `.match-table th`, `.match-table td`）。
  - スマホ表示時に横スクロールできるように、テーブルをラップする `div`（例：`.table-wrapper`）に `overflow-x: auto;` を付与。
  - `result.status` によって色分け（例：勝利=緑、敗戦=赤、未試合=グレー）するためのクラス（`.result-win`, `.result-lose`, `.result-upcoming`）。

### 5. 既存トップページとの連携

- `index.html` の「最新の試合結果」「次の試合情報」も、将来的には `matches.json` から自動取得できるようにする余地を残しつつ、
  - まずは `pages/match.html` に一覧を作る。
  - 次のステップとして、トップページ右側の試合情報ブロックを `match.js` の軽量版（または共通関数）で自動化することも可能な設計にする。

## データ更新フロー（運用イメージ）

- 担当者は `**data/matches.json` だけを編集**すればよいようにする。
- 新しい試合を追加する時は、
  - 1件分のオブジェクトをコピー＆日付・会場・相手・時間などを変更。
  - 試合前は `result.status = "scheduled"`、スコアは `null` または `0`。
  - 試合終了後に `status` を `finished` に変更し、`scoreUs`, `scoreThem` を入力。
- これにより、HTML側は一切触らずにページが最新状態になる。

## 補足（拡張アイデア）

- シーズンや大会ごとのフィルタリング機能（例：`season` フィールド追加とプルダウン）。
- スマホで見やすいカード表示（テーブルだけでなく、カード型レイアウトにも対応）。
- Googleスプレッドシートなど外部ソースと連携したい場合でも、**まずはJSONをインポート元**としておけば、後からスクリプトで変換するだけで対応可能。
